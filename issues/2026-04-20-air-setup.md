## Problem

The new Go-based `tincan-server` needed a fast local development loop with automatic rebuilds and restarts.

The repo also already had a `bin/dev-server` entrypoint, but it still pointed at the older Python backend flow.

## Solution

Set up `air` for the Go server:

- added `tincan-server/.air.toml`
- configured it to rebuild the Go server into `tincan-server/tmp/tincan-server`
- configured the dev server to run on port `8004`
- updated `bin/dev-server` to launch `air` with that config

## Notes

This keeps local iteration simple:

- edit Go files under `tincan-server`
- `air` rebuilds and restarts automatically
- the existing `bin/dev-server` command still serves as the repo-level developer entrypoint
